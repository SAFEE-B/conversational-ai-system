# Eval Suite — HealthFirst Community Pharmacy Chatbot

End-to-end evaluation suite covering correctness, tool accuracy, retrieval quality, conversational coherence, and performance.

---

## Quick Start

```bash
# 1. Install eval dependencies
pip install pytest pytest-asyncio websockets httpx chromadb sentence-transformers \
            google-generativeai matplotlib

# 2. Start the chatbot server (required for live tests)
uvicorn backend.main:app --host 0.0.0.0 --port 8000

# 3. Set env vars
export GOOGLE_API_KEY="your-gemini-key"       # required for LLM-as-judge tests
export CHATBOT_WS_URL="ws://localhost:8000/ws/chat"   # optional override

# 4. Run everything
python evals/run_evals.py

# 5. View report
cat evals/report/eval_report.md
```

### Selective runs

```bash
# Only unit tests (no server, no API key needed)
python evals/run_evals.py --no-live

# Skip latency/throughput (faster CI)
python evals/run_evals.py --no-performance

# Regenerate the report from existing result files
python evals/run_evals.py --report-only

# Run a single module
pytest evals/correctness/test_rag.py -m "not live" -v
pytest evals/performance/test_latency.py -v -s
```

## Metrics Reference

### RAG Retrieval

| Metric      | Formula | Threshold |
|-------------|---------|-----------|
| Precision@k | `|relevant ∩ retrieved[:k]| / k` | P@3 >= 0.35 |
| Recall@k    | `|relevant ∩ retrieved[:k]| / |relevant|` | R@3 >= 0.85 |
| MRR         | `mean(1 / rank_of_first_relevant)` | >= 0.80 |
| Faithfulness | LLM-as-judge score 0–1 per query, averaged | >= 0.70 |

> **Note on precision thresholds**: this corpus has one chunk per document.
> For queries with a single relevant chunk, the theoretical max P@3 = 1/3 ≈ 0.33.
> The threshold 0.35 is calibrated to this constraint; recall and MRR are the primary quality signals.

### Tool Accuracy

| Metric            | Formula | Threshold |
|-------------------|---------|-----------|
| TPR (recall)      | `TP / (TP + FN)` | >= 0.80 |
| FPR               | `FP / (FP + TN)` | <= 0.10 |
| Argument Accuracy | fraction of invocations where key result fields match expected | >= 0.75 |

### Conversational Quality (LLM-as-judge)

| Metric                | Scale | Threshold |
|-----------------------|-------|-----------|
| Task Completion Rate  | 0 / 1 per dialogue, averaged | >= 0.80 |
| Policy Adherence Rate | 0 / 1 per dialogue, averaged | >= 0.85 |
| Coherence Score       | 1–5 normalised to 0–1, averaged | >= 0.60 |

Judge model: `gemini-2.5-flash-preview-05-20` (set `JUDGE_MODEL` env var to override).

### Latency

| Metric       | Definition | Threshold |
|--------------|------------|-----------|
| TTFT         | time from message send → first token received | median <= 2.0 s |
| Inter-token  | mean gap between consecutive token messages | informational |
| E2E          | time from message send → last token received | median <= 10.0 s |

Scenarios: `simple` (plain LLM), `rag_only` (RAG, no tool), `tool_only` (one tool), `mixed` (tool + RAG).

### Throughput

| Metric                     | Definition |
|----------------------------|------------|
| throughput_tps             | total turns completed / wall-clock seconds |
| max_sustainable_concurrency | highest N where median TTFT <= 2s AND median E2E <= 10s |
| breakpoint                 | first N where either threshold is violated |

Concurrency levels tested: 1, 2, 5, 10, 20 (set `THROUGHPUT_LEVELS` in config.py).

## Environment Variables

| Variable          | Default | Description |
|-------------------|---------|-------------|
| `CHATBOT_BASE_URL` | `http://localhost:8000` | HTTP base URL for health-check |
| `CHATBOT_WS_URL`   | `ws://localhost:8000/ws/chat` | WebSocket endpoint |
| `GOOGLE_API_KEY`   | _(required for live judge tests)_ | Gemini API key |
| `JUDGE_MODEL`      | `gemini-2.5-flash-preview-05-20` | LLM judge model name |
| `CHROMA_PERSIST_DIR` | `<repo>/chroma_db` | ChromaDB index path |
| `CRM_TEST_DB_PATH` | `<repo>/crm_test.db` | Isolated CRM DB for unit tests |

## Interpreting Results

- `evals/results/` — one JSON file per test module; raw per-query/trial data
- `evals/report/eval_report.md` — human-readable summary with PASS/FAIL per threshold
- `evals/report/eval_report.json` — compact machine-readable summary for CI assertions
- `evals/report/*.png` — box plots and line charts for latency/throughput
